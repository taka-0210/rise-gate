# 問い合わせフォームの本番設定

問い合わせフォームは、入力されたメールアドレスへ自動返信しません。通知メールはサーバー側で固定された管理者アドレスだけに送信します。

## 必須の環境変数

本番サーバーの、デプロイで上書きされないルート `.htaccess` などに次を設定します。値はGitへコミットしません。

```apache
SetEnv RISEGATE_RECAPTCHA_SITE_KEY "reCAPTCHA v2 のサイトキー"
SetEnv RISEGATE_RECAPTCHA_SECRET_KEY "reCAPTCHA v2 のシークレットキー"
SetEnv RISEGATE_CONTACT_LOG_SALT "十分に長いランダムな値"
```

Google reCAPTCHA管理画面では、チェックボックス型のreCAPTCHA v2を選択し、`rise-gate.com` を許可ドメインに登録します。サイトキーまたはシークレットキーが未設定の場合、フォームは安全側に停止します。

## 緊急停止

外向きメールだけを直ちに止める場合は、サーバー側に次を設定します。

```apache
SetEnv RISEGATE_CONTACT_MAIL_ENABLED "0"
```

この状態でも、CAPTCHAを通過した問い合わせは管理画面用データへ保存されます。復旧時は値を `1` に変更します。

## 制限と記録

- 同一送信元: 1分に1回、1時間に3回まで
- サイト全体: 1時間に20回まで
- セキュリティ状態と監査ログ: デフォルトでは公開領域外の `tmp/contact-security/`
- 本文: 5,000文字まで
- リクエスト全体: 32 KiBまで

保存先を変更する場合は `RISEGATE_CONTACT_SECURITY_DIR` に、Webから直接参照できない書き込み可能な絶対パスを設定します。制限用ファイルやログを削除すると監査情報とレート制限状態が失われるため、通常運用では削除しません。

## XServerへの解除依頼前

1. reCAPTCHA v2のキーを本番サーバーへ設定する。
2. 手動デプロイ後、国内環境から正常送信を1回確認する。
3. 入力者宛の自動返信が届かず、固定管理者宛だけに通知されることを確認する。
4. サーバー上のPHPファイルを正規リポジトリと比較し、不審ファイルや改ざんがないことを確認する。
5. 国外アクセス制限の `all` は削除せず、対策内容をXServerへ報告して解除を依頼する。
